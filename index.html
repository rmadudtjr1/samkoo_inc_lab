CHAPTER 0

왜 Gemini Enterprise인가

우리는 이미 Google Workspace를 씁니다. Gemini Enterprise는 그 위에 회사 데이터 전체를 내 권한만큼 검색하고, 그 위에 에이전트를 만들어 공유하는 회사용 AI 작업공간을 더합니다.

이론 1생성형 AI는 어떻게 답을 만드나

Gemini 같은 대규모 언어 모델(LLM)은 아주 많은 글을 학습해, 주어진 문장 다음에 올 말을 이어 쓰는 방식으로 답을 만듭니다. 그래서 문장력과 요약·정리 능력은 뛰어나지만 두 가지 약점이 있습니다.

우리 회사 일을 모릅니다사내 규정, 이번 분기 점검 결과, 어제 올라온 티켓은 학습 데이터에 없습니다.
모르면 지어낼 수 있습니다그럴듯하지만 틀린 답을 환각(hallucination)이라고 합니다. 조항 번호나 날짜가 특히 위험합니다.
질문이 곧 설계도입니다모델은 질문에 담긴 정보(컨텍스트)만큼만 압니다. 역할·자료·형식을 주면 결과가 달라집니다.

이론 2그라운딩: 먼저 찾고, 찾은 것으로 답하기

두 약점을 줄이는 방법이 그라운딩입니다. 답하기 전에 사내 문서나 웹에서 관련 내용을 먼저 찾고, 찾은 내용을 근거로 답하게 합니다. 이 방식을 검색 증강 생성(RAG)이라고도 부릅니다. Gemini Enterprise 어시스턴트는 기본적으로 이렇게 동작하며, 검색 단계에서 내가 볼 권한이 있는 문서만 찾습니다.

이론 3Gemini Enterprise는 네 층으로 되어 있습니다

오늘 실습은 위 두 층(화면과 에이전트)에서 합니다. 데이터 층의 커넥터 연결과 오른쪽 거버넌스는 관리자 영역이라 설명만 합니다.

  • Gmail·문서·Drive 안에서 돕는 개인 비서
  • 주로 내가 열거나 지정한 파일을 다룸
  • Gems로 반복 지시를 저장

  • 에이전트·스킬·프로젝트를 만들어 팀에 공유
  • 관리자가 기능·커넥터·공유를 통제하고 사용 내역을 분석

CHAPTER 0 · 참고

Gemini Enterprise에만 있는 것

Workspace의 Gemini로는 할 수 없거나 훨씬 제한적인 기능 여섯 가지입니다. 앞의 세 개는 무엇을 할 수 있는가, 뒤의 세 개는 회사가 어떻게 통제하는가에 관한 것입니다.

활용 1설명

사내 시스템을 한 번에 검색

  • Drive·Gmail·캘린더에 더해 SharePoint·OneDrive·Outlook, Jira, Confluence, ServiceNow 등을 커넥터로 연결
  • 데이터를 색인에 복사하는 방식과, 복사 없이 원본에서 바로 찾는 방식 중 선택
  • 원본 시스템의 사용자·그룹 권한을 함께 동기화해, 볼 수 있는 사람에게만 결과 표시

보안·IT팀에서는규정(Drive), 장애 티켓(ITSM), 점검 기록을 한 질문으로 엮어 찾기

활용 2Ch.4 실습

에이전트를 만들고 한 곳에 모으기

  • Workflow Builder: 코딩 없이 대화형 에이전트와 워크플로(조건 분기·사람 승인·예약 실행)
  • Google이 만든 에이전트(Deep Research 등)
  • 개발팀이 ADK·A2A·Dialogflow로 만든 에이전트도 등록해 같은 에이전트 갤러리에서 사용

보안·IT팀에서는현업이 만든 노코드 에이전트와 개발팀의 검증 도구를 한 창구로 제공

활용 3Ch.2·3 실습

팀 단위 작업공간과 확장되는 스킬

  • 프로젝트: 자료 50개 + 여러 채팅 + 팀원을 한 곳에
  • 스킬: 아무 채팅에서 /로 호출, Python·Bash 스크립트로 계산·파일 처리까지
  • 정식 라이선스에서는 Gemini 외 Claude 등 모델 선택

보안·IT팀에서는분기 점검 프로젝트 하나에 자료·작업 이력을 모으고 보고서 형식을 통일

통제 1관리자 기능 · 설명만

Model Armor

  • 프롬프트: 악성 입력, 프롬프트 인젝션, 탈옥, 민감정보 검사
  • 응답: 데이터 유출, 유해 콘텐츠, 악성 URL 검사
  • ‘검사 후 차단’ 또는 ‘검사만’ 선택, 위반 첨부 파일은 요청에서 제외

보안·IT팀에서는규정 제14조(민감정보 입력 금지)를 교육이 아닌 시스템으로 강제

통제 2관리자 기능 · 설명만

에이전트 거버넌스

  • 직원이 에이전트를 공유할 때 관리자 검토·승인을 거치도록 설정
  • 문제 있는 에이전트는 일시 중지
  • 기능별 켜기/끄기, 사용 현황 분석

보안·IT팀에서는누가 어떤 에이전트를 만들어 누구에게 퍼뜨리는지 파악·통제

통제 3관리자 기능 · 설명만

Google Cloud 보안 통제와 인증

  • VPC Service Controls, 고객 관리 암호화 키(CMEK), 데이터 저장 위치 지정, Access Transparency
  • ISO 27001·27017·27018·27701, SOC 1·2·3 등 인증 (Standard·Plus 기준)
  • Google Cloud IAM으로 관리자 권한 분리

보안·IT팀에서는기존 GCP 보안 정책 안에서 AI를 운영하고 감사 자료로 활용

주의통제 1~3은 관리자 권한이 필요해 오늘은 설명만 합니다. 일부 통제는 조건이 있습니다. VPC Service Controls·Access Transparency는 Google 검색 기반 답변을 켜면 적용되지 않고, CMEK는 US·EU 멀티 리전에서만 지원합니다. Model Armor는 ADK·A2A로 직접 만든 에이전트는 검사하지 않고, Antigravity는 ISO·SOC 인증 범위에 들어가지 않습니다. 외부 커넥터 전체는 Standard 이상 에디션에서 쓸 수 있습니다.

# 보안 점검 보고서 작성법

## 순서
1. 한 줄 결론: 위험 건수와 가장 급한 조치 1개
2. 요약 표: 구분 | 건수 | 위험도(상/중/하)
3. 상세 표: 번호 | 대상 | 문제 | 근거 조항 | 위험도 | 조치 | 조치 기한 | 담당 부서
4. 다음 점검 때 볼 것 3가지

## 규칙
- 위험도: 퇴사자·휴직자 계정 활성 = 상, 승인 없는 관리자·공용 계정 = 상, 90일 미사용 = 중, 그 외 = 하
- 조치 기한: 상 = 1영업일, 중 = 5영업일, 하 = 다음 분기 검토 전
- 근거 조항이 없으면 "규정 확인 필요"로 표시하고 추측하지 않는다
- 이름은 성+OO 형태로 가린다 (예: 김OO)
- 문장은 짧게, 존댓말 보고체로 쓴다

이론챗봇과 에이전트는 무엇이 다른가

지시문과 지식은 다릅니다지시문은 “어떻게 일할지”, 지식은 “무엇을 보고 판단할지”입니다. 규정 원문은 지식에 넣고, 지시문에는 그 규정을 어떻게 적용할지만 적습니다. 그래야 규정이 바뀌어도 파일만 교체하면 됩니다.
테스트 → 고치기 반복정상 사례, 함정 사례(예외 승인 계정), 역할 밖 질문 세 가지로 시험하고, 틀린 부분은 지시문에 기준을 한 줄씩 더합니다. 에이전트가 쓰는 도구와 데이터는 관리자가 허용한 범위 안으로 제한됩니다.

강사와 함께‘권한 체계 검토 에이전트’

  1. 왼쪽 메뉴 에이전트 > 에이전트 만들기 (Workflow Builder에서 대화형 에이전트)
  2. 이름: 권한 체계 검토 도우미. 아래 지시문을 붙여 넣습니다.
  3. 지식에 자료 A(규정)를 추가합니다.
  4. 미리보기 창에서 자료 B(계정·권한 현황)를 첨부하고 “이번 분기 검토해 줘”라고 테스트합니다.
  5. 결과가 마음에 들면 게시하고 옆자리 동료에게 공유합니다.

## 역할

## 검토 기준 (기준일은 사용자가 말하지 않으면 오늘 날짜)

## 답변 형식

[보안 점검 요청] 협력사 출입 신청 웹 (교육용 가상 자료)
요청 부서: 시설관리팀 · 오픈 예정일: 2026-11-20 · 요청일: 2026-10-29

1. 개요
협력사 직원이 사업장 출입 전에 웹에서 출입을 신청하고, 시설관리팀이 승인하는 서비스입니다. 외부 인터넷에 공개됩니다.

2. 로그인
협력사 직원은 회원가입 후 아이디와 비밀번호로 로그인합니다. 비밀번호는 8자 이상이면 가입됩니다. 2단계 인증은 사용자 불편으로 적용하지 않았습니다.

3. 수집 정보
이름, 휴대전화 번호, 소속 회사, 차량 번호를 수집합니다. 신청 화면에 개인정보 수집·이용 동의 체크박스가 있습니다. DB 암호화는 오픈 후 2차 개발에서 적용할 예정입니다.

4. 관리자 기능
시설관리팀이 /admin 페이지에서 신청을 승인합니다. 관리자 계정은 시설관리팀 공용 계정 1개를 함께 씁니다. 외부에서도 /admin 접속이 가능해 현장에서 휴대폰으로 승인할 수 있습니다.

5. 기술 사항
- 전 구간 HTTPS 적용(인증서 발급 완료)
- 입력값은 프레임워크 기본 검증 기능 사용(SQL 인젝션·XSS 필터 포함)
- 접속 기록은 6개월 보관 후 자동 삭제
- 오류 발생 시 사용자에게 "일시적인 오류입니다" 안내 화면 표시
- 30분 동안 활동이 없으면 자동 로그아웃
- 백업: 클라우드 일일 자동 백업. 복구 절차 문서는 작성 중
